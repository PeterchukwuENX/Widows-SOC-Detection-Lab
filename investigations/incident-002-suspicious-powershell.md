Case 002 — Suspicious PowerShell Execution
What I investigated
I wanted to practice investigating PowerShell activity from the perspective of a SOC analyst.
I generated a controlled PowerShell execution using an encoded command and then reviewed the activity through Sysmon Event ID 1.
Evidence
Sysmon recorded a process creation event for:

```text
powershell.exe

The command line contained:
powershell.exe -EncodedCommand

The event also showed:
- User: WINDOWS-SOC-LAB\kenny
- Current Directory: C:\Users\kenny\
- Event ID: 1
- Source: Sysmon

Analysis
The use of -EncodedCommand caught my attention because encoded PowerShell commands can be used to hide the actual command being executed.
However, I would not immediately classify the activity as malicious.
This was a controlled command generated by me inside the lab.
A real SOC investigation would continue by checking:
- The decoded command
- Parent process
- Child processes
- User context
- Network connections
- Related PowerShell events
- Other activity around the same timestamp
Finding
Classification: Suspicious but benign lab activity
The investigation demonstrated how Sysmon can capture PowerShell process creation and command-line information.
The main lesson was that a suspicious indicator should trigger further investigation rather than an automatic malicious verdict.
What I learned
I practiced:
- Sysmon Event ID 1 analysis
- PowerShell investigation
- Command-line analysis
- Recognizing encoded PowerShell
- User and process context
- Evidence-based classification
